# 中文个人学术主页设计

## 目标与已确认范围

基于 https://github.com/tangjyan/zh-cn 搭建中文为主的个人学术主页，保留 Jekyll 和双栏布局，适度优化排版。用户已确认本方案。计划开源至 `yyx-9527/yyx-9527.github.io`，通过 GitHub Pages 发布。

## 方案对比与选择

- 原样替换内容：改动最少，但保留旧模板中写死的路径和维护方式。
- 保留模板、整理数据并优化排版（已选择）：沿用 Sass、布局与组件结构，改善中文阅读和移动端表现，提供独立的个人资料、论文数据和自动部署流程。

## 架构与内容

- Jekyll 将 `_config.yml`、`_data/` 和 `_pages/about.md` 编译成静态网站。
- 个人资料在 `_config.yml` 维护；简介使用 Markdown；研究方向、论文、教育经历分别使用 YAML 数据。
- 左侧为姓名、头像、机构、邮箱与学术链接；右侧为个人简介、研究方向、论文列表、教育经历、联系方式。
- 白色背景、深蓝链接、细分隔线；中文采用本机可用中文字体，无远程字体依赖。
- 资料缺失显示“待补充”，不复制模板作者的身份、经历、论文或引用数据。空链接不生成按钮。
- 保留原 MIT 许可和上游来源说明。Google Scholar 统计默认关闭，需要配置后显式启用。
- GitHub Actions 构建 Jekyll，验证产物后部署到 Pages；PR 只检查构建。

## 验证

实际执行 Jekyll 构建，检查站内资源、锚点与配置；在桌面和手机宽度检查页面、导航和横向溢出。部署时核对目标 GitHub 账号和权限；只有确认远程发布成功后才报告上线。

## 实施顺序

1. 导入上游模板并保留许可。
2. 替换个人资料、整理数据文件、实现页面和移动导航。
3. 更新构建依赖、CI / Pages 工作流、维护和发布文档。
4. 构建与浏览器检查，修复问题，提交本地改动。
5. 使用目标账号发布并验证公开访问。

当前环境没有 `writing-plans` 技能，以上实施顺序作为本项目的实施计划。
